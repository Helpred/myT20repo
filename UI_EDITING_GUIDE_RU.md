# Редактирование GUI и добавление карт в Godot 4.7

В этой сборке статический GUI лежит в `client/scenes/ui/` и редактируется как обычные 2D-сцены. Игровая и сетевая логика остаётся в GDScript/Python.

## Где что лежит

- `res://scenes/ui/profile_strip.tscn` — верхняя панель: звание, XP, прогресс, кристаллы.
- `res://scenes/ui/auth_screen.tscn` — вход/регистрация.
- `res://scenes/ui/lobby_screen.tscn` — список битв, верхнее меню, информация о выбранной битве и чат.
- `res://scenes/ui/create_battle_dialog.tscn` — создание битвы и выбор карты.
- `res://scenes/ui/battle_list_item.tscn` — шаблон строки списка битв.
- `res://scenes/ui/garage_screen.tscn` — гараж.
- `res://scenes/ui/garage_item.tscn` — карточка предмета гаража.
- `res://scenes/ui/battle_hud.tscn` — HUD боя.
- `res://scenes/ui/round_overlay.tscn` — результаты раунда.

## Почему раньше Position/Size были заблокированы

`HBoxContainer`, `VBoxContainer` и `GridContainer` автоматически расставляют своих прямых детей. Поэтому Godot показывает предупреждение «Этот узел — дочерний узел контейнера» и не разрешает свободно менять Transform.

В этой версии визуальные/редактируемые элементы внутри таких контейнеров помещены в промежуточные обычные `Control`-узлы с суффиксом `Slot`.

Пример:

`Top -> RankXPSlot -> RankXP`

Контейнер управляет только `RankXPSlot`, а сам `RankXP` является ребёнком обычного `Control`. Выбирай **RankXP**, а не `RankXPSlot`: Position/Size/anchors можно менять вручную.

Кроме того, в каждой UI-сцене есть пустой `FreeCanvas`. Если нужно полностью свободное позиционирование, перетащи нужный визуальный узел из `...Slot` в `FreeCanvas`. Код ищет функциональные узлы рекурсивно по имени, поэтому менять родителей теперь можно. Главное — сохранить имя узла и не создавать второй функциональный узел с тем же именем.

## Как менять картинки

Для `TextureRect`, `TextureButton`, `TextureProgressBar` меняй `Texture`, `Texture Normal`, `Texture Under`, `Texture Progress` и Stretch Mode в Inspector.

Старые UI-текстуры: `res://assets/ui/legacy/`.

Полоса звания:

- `res://assets/ui/rank_progress_empty.png` — пустая;
- `res://assets/ui/rank_progress_full.png` — заполненная.

`profile_strip.tscn -> Cluster -> RankProgress` — настоящий `TextureProgressBar`. Код меняет только `value` 0..1.

# Карты: автоматический каталог

Ручного списка карт в `main.gd` и `server.py` больше нет. Клиент и сервер сканируют:

`res://scenes/maps/*.tscn`

То есть для новой карты достаточно:

1. Создать/дублировать сцену, например `arena_day.tscn`.
2. Положить/сохранить её в `client/scenes/maps/`.
3. Убедиться, что в сцене есть `Marker3D` с именами `Spawn_0`, `Spawn_1`, ... (лучше минимум три).
4. Открыть «Создать битву». Карта появится в выпадающем списке автоматически.

Сервер также пересканирует `client/scenes/maps` при открытии/обновлении списка битв и при создании битвы. Править Python при добавлении новой `.tscn` не требуется.

## Имя карты

По умолчанию имя строится из файла:

- `arena_editable.tscn` -> `Арена` (совместимость с основной картой);
- `arena_day.tscn` -> `Arena Day`;
- `winter_factory.tscn` -> `Winter Factory`.

Если хочется красивое русское имя, на **корневом узле сцены** добавь Metadata через Inspector:

`tanki_map_name = Арена — день`

Это необязательно.

## Превью карты

Превью тоже ищется автоматически. Достаточно положить картинку с тем же именем:

`client/scenes/maps/arena_day.tscn`
`client/scenes/maps/arena_day.jpg`

Поддерживаются `.png`, `.jpg`, `.jpeg`, `.webp`.

Альтернативно можно положить `arena_day.png` в `res://assets/ui/maps/`.

Если превью нет, используется стандартная картинка-заглушка.

## Spawn points

Сервер автоматически считает `Spawn_N` в `.tscn`. Минимальная ёмкость комнаты сохраняется в 9 слотов: если реальных точек меньше, клиент создаёт дополнительные боковые позиции относительно существующих Spawn-маркеров. Для совершенно новой геометрии лучше вручную поставить `Spawn_0`, `Spawn_1`, `Spawn_2` и при желании `Spawn_3...`.

Если в карте вообще нет `Spawn_N`, остаётся аварийный fallback старой Арены — так делать не рекомендуется.

## Что можно менять без правки кода

- положение и размеры 2D-элементов;
- родителей визуальных элементов (в том числе переносить в `FreeCanvas`);
- anchors/offsets;
- текстуры, шрифты, цвета;
- размеры окон/панелей;
- внешний вид кнопок;
- расположение HUD;
- шаблон строки битвы и карточки гаража;
- добавлять новые `.tscn` карты;
- добавлять превью к картам.

Функциональные узлы лучше **не переименовывать**: `Login`, `Password`, `Host`, `Port`, `BattleList`, `Search`, `JoinBattle`, `GarageGrid`, `RankIcon`, `RankXP`, `RankProgress`, `Amount`, `KillProgress`, `Kills`, `Fund`, `SuppliesText` и т. п. Родителя менять можно — код теперь использует рекурсивный `find_child()`.
