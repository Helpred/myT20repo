TANKI 2.0 GODOT — МОДИФИКАЦИИ M0–M3 (RELEASE 20)
====================================================

ГДЕ МЕНЯТЬ ЦЕНЫ, РАНГИ И ПРИВЯЗКУ МОДЕЛЕЙ
------------------------------------------
Главный конфиг модулей:
    server/data/loadout_catalog.json

Для каждого корпуса/башни там есть четыре записи mod=0..3.
Поля:
    id                 техническое имя модуля (wasp, viking, mamont, smoky, firebird, thunder)
    mod                логическая модификация 0..3
    base_name          имя модуля без M-уровня
    name               отображаемое имя, например VIKING M2
    price              цена ПОКУПКИ M0 (для M1..M3 обычно 0)
    upgrade_price      цена перехода с предыдущего M на эту модификацию
    min_rank           минимальный индекс звания для улучшения до этой модификации
    visual_source_mod  справочная отметка: из какой старой модели взят текущий визуал
    asset_model        res:// путь к 3D-модели именно этой модификации
    asset_texture_dir  res:// каталог текстур именно этой модификации

Индексы званий находятся в:
    server/data/economy.json -> ranks

Индекс начинается с 0:
    0  Новобранец
    1  Рядовой
    2  Ефрейтор
    ...
    5  Сержант
    10 Уорэнт-офицер 1
    15 Младший лейтенант
    ...
    26 Маршал

В текущем релизе по умолчанию:
    M0 — ранг 0 (доступна к покупке сразу)
    M1 — ранг 5  (Сержант)
    M2 — ранг 10 (Уорэнт-офицер 1)
    M3 — ранг 15 (Младший лейтенант)

Это НЕ зашито в код: можно поменять min_rank отдельно у любой записи.

ТЕКУЩИЕ МОДЕЛИ
---------------
Новых 3D-моделей для M0/M1/M2/M3 пока нет, поэтому все четыре логические
модификации используют существующую модель модуля:
    Wasp     -> wasp_m2.dae
    Viking   -> viking_m1.dae
    Mamont   -> mamont_m3.dae
    Smoky    -> smoky_m2.obj
    Firebird -> firebird_m1.obj
    Thunder  -> thunder_m3.obj

Если позже появится, например, viking_m2.dae:
1. положить модель и её текстуры в client/assets/...;
2. у записи viking/mod=2 в loadout_catalog.json изменить asset_model и asset_texture_dir;
3. заново экспортировать клиент, чтобы ресурс попал в PCK/EXE.
Сервер передаёт привязку клиенту в каталоге, поэтому tank.gd менять не нужно.

БОЕВЫЕ ХАРАКТЕРИСТИКИ M0–M3
----------------------------
Множители характеристик находятся в:
    server/data/combat_stats.json -> modifiers

Сейчас:
    M0  hp x1.00, damage x1.00, reload x1.00, fuel x1.00
    M1  hp x1.15, damage x1.16, reload x0.96, fuel x1.08
    M2  hp x1.32, damage x1.34, reload x0.92, fuel x1.16
    M3  hp x1.52, damage x1.55, reload x0.88, fuel x1.25

Для корпуса используется hp, для оружия damage/reload/fuel по типу оружия.

ПОКУПКА И УЛУЧШЕНИЕ
--------------------
- новый модуль всегда покупается как M0;
- M1 можно открыть только имея M0;
- M2 — только имея M1;
- M3 — только имея M2;
- сервер проверяет кристаллы, ранг и последовательность;
- если улучшается установленный модуль, новая M-модификация ставится автоматически.

МИГРАЦИЯ АККАУНТОВ 19.x
-----------------------
Старые аккаунты не обнуляются. Если до Release 20 у игрока был, например,
Wasp M2, при первом чтении профиля сервер считает, что он уже прошёл M0 -> M1 -> M2
и добавляет ему нижние уровни без списания кристаллов. Установленный M2 остаётся M2.
Новые аккаунты начинают с Wasp M0 + Smoky M0.

РАНГОВЫЕ БИТВЫ И БОТЫ
----------------------
При создании битвы выбираются минимальное и максимальное звание.
Сервер не пустит игрока, чей rank index находится вне диапазона.
Создатель также обязан сам входить в выбранный диапазон.

Ранг бота случайно выбирается ВНУТРИ диапазона битвы. После этого корпус/башня и
их M-уровни выбираются только из тех записей loadout_catalog.json, у которых
min_rank <= rank бота. Поэтому бот ниже требуемого звания физически не получит M1/M2/M3.
