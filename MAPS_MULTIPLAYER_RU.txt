Tanki 2.0 — карты в экспортированной игре (release 19.0.0; система карт из ветки 18.18.30)
================================================================

Почему старый вариант ломался
-----------------------------
После Godot Export папка res:// находится внутри PCK/EXE. Это не обычная
записываемая папка, поэтому схема «найти новые res://scenes/maps/*.tscn»
подходит редактору Godot, но не пользовательским картам в готовой игре.

Новая схема
-----------
1. Сервер — источник истины для мультиплеерных карт.
2. Сервер хранит карты в server/maps/*.tscn.
3. При входе клиент получает каталог карт с SHA-256.
4. При входе в битву клиент автоматически скачивает точную .tscn с сервера
   по HTTP и кеширует её в user://server_maps/.
5. Поэтому карта больше НЕ обязана быть зашита в EXE каждого игрока.

Локальные карты в экспортированной игре
---------------------------------------
При первом запуске рядом с EXE автоматически создаётся папка:

    maps/

Туда можно положить Arena-derived файл, например:

    arena_day.tscn

Он появится в меню создания битвы. При создании битвы клиент автоматически
загрузит .tscn на сервер. Сервер сохранит её в server/maps/, а остальные
игроки скачают карту сами при подключении.

ВАЖНО: текущий формат пользовательских карт по исходному ограничению проекта допускает только варианты
Арены и передаёт только .tscn. Карта должна ссылаться на ресурсы Арены,
которые уже входят в клиент. Новые пользовательские GLTF/JPG/PNG/LMBake,
которых нет в сборке клиента, этим патчем пока не распространяются.

Как назвать карту
-----------------
Имя файла становится ID:

    arena_day.tscn -> arena_day

Красивое имя можно задать Metadata у корневого Node3D:

    tanki_map_name = Арена — день

Встроенный ID arena зарезервирован. Пользовательский вариант нужно сохранить
под другим именем.

Припасы
-------
В arena_editable.tscn теперь есть:

    SupplyPoints
      Supply_0
      Supply_1
      ...
      Supply_31

Это Marker3D. Сервер читает их координаты прямо из конкретной .tscn карты.
Можно двигать эти точки в Godot, удалять и добавлять новые Supply_N.

Для старых Arena-derived карт, созданных до появления этих маркеров,
сохраняется fallback: если сцена использует стандартную геометрию Arena,
сервер автоматически применяет старые проверенные 32 точки падения.
Поэтому дневная/ночная версия старой Арены получает припасы без ручного
подключения к supply_drop_zones.json.

Точки спавна
------------
Spawn_0, Spawn_1, ... по-прежнему читаются из самой сцены карты.

Сеть
----
Сетевой протокол release 19.0.0: v11.
Клиент и сервер должны быть обновлены одновременно.
HTTP asset-port (по умолчанию UDP 9100 + HTTP 9101) теперь раздаёт не только
покрытия, но и карты.
